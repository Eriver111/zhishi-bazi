# 今日引动与提醒：依据与边界（2026-09-24）

## 本轮目的

用户质疑今日运势缺少依据，随后要求继续优化。本轮只修改今日运势的个人推演、展示及相应测试；不改基础排盘、旺衰、格局、家庭关系、报告校准、支付或生产数据。

旧版以喜用忌数组加固定分数，直接给合化目标加分，累加相同关系；大运流年流月仅进入 AI 提示。模型又被要求扩写具体应事，资料不足时仍可能仅凭日柱生成个人运势。

## 当前计算约定

- `api/_daily-fortune.js` 使用 `getYongJi` 和 `classifyFortuneElement` 的现有共用作用证据、原局/增量条件及干支载体复核。保留条件有利、中性双向，不再将结构忌神直接当作流日纯凶。
- 移除每日吉凶累计分；以“当天直接关系 → 作用方向与条件 → 岁运背景牵制/同字重见”产生定性标签。这是明确的软件规则，不是经验证的吉凶概率或传统公认的唯一标准。
- 相同流日载体对原局重复同字合并为一条关系，保留所有宫位目标；六合与相破、五合与克制等同组事实一并列出，不叠加奖惩。伏吟只作观察，不独立扣分。
- 天干五合、六合、三合/三会三支补齐均不直接认定合化。原局已有三支，不把流日重见说成新成局。半合半会不再独自加分；刑害破的单一名目不独自定强烈应事。
- 大运、年、月分别检查与当天同层干/支的直接同字、合冲克制等关系。背景能限制有利作用，或标识已有压力重见；没有当天原局引动时，不因背景喜用就天天报吉。背景关系不按条数加分。
- 暂未实现将原局、大运、年、月、日合并重排后的完整生克制化裁决，也没有跨所有层次补齐三合/三会后实化的判断。背景的生克是关系记录与保守限制，不是证明该作用已经成功实现。
- 日柱使用共用历法；按中国标准时间换日。年/月节气归属及所处大运以当日12时作日级参考，不细分交节、交运当天前后，并在页面说明。
- 大运转接按核心 `startDate` 的民用日期分量判定、使用出生精确钟点，不再只看 startYear/endYear。无出生日期/未起运/超范围明确标识，缺具体钟点的旧档案按时辰中点估算并提示。

## 当前文案及同日定版（接续第55节）

用户指出固定模板重复，并要求同一命盘同一天不得出现两套措辞。当前实现取代第54节完全取消AI的第一版，但不恢复模型自由推断。

- `api/_daily-fortune-copy.js` 从最主要的强引动选一条依据，比较昨天的同类主题；相同则说明延续，不把每天换一个日期当作新主题。不同则点出当天主要关系。标题、倾向、作用条件及具体场景建议仍由规则产生。
- 有既有AI配置时，flash模型只改写一条已锁定的引动解释，不接收姓名、出生信息、任意档案标签或用户自由文本。要求JSON、引用干支、保留关系名和原有限制，限制长度、新增关系/干支及具体事件预测。未通过、超时或无模型配置使用含当天具体依据的规则版。
- 自动校验是有限的格式、关系和措辞检查，不能声称语义等价已被形式证明；没有用真实模型输出或用户经历验证准确率。低温度本身不保证同一句话，同日一致性由持久化快照保证。
- `lib/daily-fortune-store.js` 按中国日期＋规范化命盘身份存储。身份包含四柱、性别及已知出生日期/具体钟点，排除名称、账号、URL参数顺序、模型或代码版本。等价整数钟点＋分钟与小数钟点归一；同一时辰不同具体钟点保留差异。补齐/修改出生资料形成不同身份。
- 全文、标题、依据、条件一并定版，首页与详情共用。首次生成的规则回退也是当天正式版本，AI恢复后不悄悄替换。代码更新不另开同日版本；次日请求生成下一份。
- 同进程并发合并为一次生成；跨进程用临时文件写入、fsync后原子无覆盖link发布，所有参与者读取获胜文件。跨进程极端竞态可能重复调用模型，但只能发布并展示一份，不能声称分布式模型调用严格仅一次。
- 只有持久化成功才返回正文。文件损坏/读写失败返回503，不拿另一份临时文案冒充已保存版本。用户必须先鉴权，即使读取已缓存内容；原有限频保留。

个人输入需有完整出生日期/时辰/性别，或完整合法四柱。仅日柱、无效日期、无法建盘等返回 `fortune:null` 与补齐资料提示；计算异常不能伪装“平稳”。直接四柱缺出生日期仍可观察当天关系，但不伪造大运。

保持今日运势入口，主页卡片为“今日引动与提醒”。详情先展示提醒，再展开“推演依据与适用条件”；包含原局引动、岁运背景、干支作用条件和数据范围。同柱重复条件去重，文本转义。具体安排建议以“如果今天有作业、任务、约定”等条件场景表达，不从年龄单独假定已经工作或结婚。本轮没有增加生活身份选择器，也没有接入报告的经历校准数据。

快速切换档案使用请求序号防止旧响应覆盖当前命盘；主页及详情均不把资料缺失当作平稳。`home-fortune.js`缓存版本3。公共黄历的民俗内容未改，不作为个人结论。

## 快照存储与部署条件

现有ECS/PM2部署使用持久本地文件，无需数据库迁移。默认目录为项目上一级的 `.zhishi-private/daily-fortune`，也可通过 `FORTUNE_CACHE_DIR` 指定绝对路径。目录必须在网站静态根之外，代码同时检查符号链接解析后的实际路径。目录/文件创建权限分别为0700/0600；保存命盘身份摘要与结果，不保存原始出生输入或账号信息，但结果仍按私有数据管理。

发布前需确保运行账号可创建、读写该目录，并保留目录跨重启/部署；不能用临时容器层代替。多实例需共享同一支持原子link的持久文件系统；多台服务器独立磁盘或无状态平台不能据此宣称跨节点定版，需要接入共享存储后再使用。创建新日快照时清理早于14天的本模块快照，不递归删除目录或处理无关文件。本轮没有登录生产服务器或改变生产配置。
