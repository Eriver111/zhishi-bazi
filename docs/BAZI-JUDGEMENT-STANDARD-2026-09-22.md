# 旺衰、喜用忌、格局：判定标准与验证方向

2026-09-22。本轮核对基线为 `bc34314`。用户明确：问真不提供这三项判断，而这三项是最希望做标准的核心内容。本文记录目标、现状和后续验收要求，不表示已更换算法、完成外部验证或获得所有流派认可。

用户随后认可并要求调整，已实施的第一批修复及审计工具保护见 [调整报告](BAZI-JUDGEMENT-ADJUSTMENT-2026-09-22.md) 与 [规则v1](BAZI-JUDGEMENT-RULES-V1.md)。本文下述“尚未实施”描述的是提出方向时的状态，具体完成范围以上述报告为准。

## 对照范围

- 历法排盘：四柱、节气边界、起运等以已经观察到的问真输出及明确的历法口径核对；尚未实测的范围仍保留限制。
- 命理判读：知时必须有明确采用的规则、可复核的依据和单独的验收样本。问真排盘一致不能证明旺衰、喜用忌或格局判断正确。
- 程序回归：1,063 项测试是上一轮限定范围的程序与规则回归结果，不是三项判读的准确率，也不能作为古籍观点或真实人生预测的证明。

## 已有基础与优先核实内容

以下为 `js/bazi.js` 当前实现的核对记录；“待核实”不能直接当作确定缺陷，更不能据此立即重调分数。

| 项目 | 当前实现 | 下一步标准必须回答的问题 |
| --- | --- | --- |
| 旺衰 | `calcDayMasterStrength` 结合月令、根气、透干和生克条件，最终由 30/40/60/80 分界映射档位；`buildBaziEvidenceSettlement` 提供有效证据结算 | 哪些证据足以支持每个档位？同一根气或冲合是否重复加扣？边界盘能否有理由地偏强或偏弱，而不只报分数？ |
| 从格、专旺 | `getCongGe` 独立判定；成立后覆盖普通格局与取用，另有假从候选 | 承认哪些破从条件、微根和透印条件？成立、候选与普通身弱的界限是什么？哪些是项目取法，哪些仍有争议？ |
| 格局 | `getPattern` 先取基础格；`adjudicatePattern` 等再裁定复合结构，最终通过 `getYongJi().resolvedPattern` 统一输出 | 取到格名、满足成格条件、破格、救应和兼见结构应分别验收；不能把看到两个十神视为通路已成立。 |
| 喜用忌 | `calcCandidateScores` 结合扶抑、结构与调候；存在明确的短路条件，`finalizeYongJiResult` 说明取用来源和作用边界 | 每个优先例外须有适用条件及反例；取用冲突不能只靠总分高低解释。需要区分原局作用、是否已经到位、是否适宜再增及岁运载体。 |

标准化先形成规则清单，再用案例校验实现。每条规则记录：编号、采用口径、可核验来源或项目约定、必要条件、否决条件、与其他规则冲突时的裁决、正例和反例。旧规则文档已经过时，不能用其旧分数和旧优先级替代当前核查。

## 验收样本不能直接等同于已有测试答案

保留现有 `audits/bazi/round-01` 至 `round-08` 的原始材料及冻结哈希。冻结能证明材料未被修改，不能证明判断正确或来自外部专家。后续基准须记录裁判来源、采用规则版本、独立判断时间、复核者和异议；没有这些证据时只能称内部审计，不能宣传为外部金标准。多个 AI 结论一致也不足以替代来源和复核。

本轮发现第八轮独立判断存在可直接核对的事实问题：

- `R08-C03` 的四支为子、寅、卯、酉，判断却以“只得丑根”为旺衰依据。
- `R08-C04` 的四支为子、寅、卯、亥，旺衰、格局和争议说明却多次引用丑根；还将己土日主所见的亥中甲木称为印。

证据位于 `audits/bazi/round-08/cases.json` 与 `independent-rulings.md` 的对应案例。上述两盘的既有判断标记为**待独立复核，不作验收标准**；这是本轮审计使用约束，尚未新增程序自动拦截。原始文件与冻结记录不改，纠正须另留版本记录。发现裁判错误并不意味着网站结论因此正确，也不能直接据此重判两盘的旺衰、从格或用神。

后续样本分为三类：用于推导和修正规则的开发样本、冻结后不参与调参的验收样本、保留多种取法及原因的争议样本。三项分别统计符合明确标准的比例、事实错误数及待定数，公开分母和争议样本，不能将所有差异都归为流派不同，也不能将所有不一致都当成程序错误。

既有比较表的 `match` 口径也不统一：第八轮将部分“偏弱/极弱”记为一致，并允许部分喜神集合不等时记为一致；不能把该列直接汇总成准确率。后续需预先区分强弱方向、具体档位、首用五行、喜忌集合、格局名称与成立状态，并分别报告。只读复核未发现 80 盘四柱重复，但当前去重脚本跳过 `audits`，登记表也只登记第一轮，后续需补上跨轮自动去重及标签完整性检查。

## 后续实施顺序

1. 先清理审计基准中的硬事实错误，补齐来源和裁决记录；不把旧回归答案反向当成新标准。
2. 优先审查旺衰与从格边界，覆盖得令无根、失令有强根、印旺但生扶受阻、强弱临界等结构；先冻结判定依据，再比较引擎。
3. 同批追踪基础格、最终格局及喜用忌的连锁结果，核对格局成立/破损条件和取用主次；对有争议的情形保留条件与替代解释。
4. 每次修正规则后运行同类未见盘和相反结构的回归，并核对结果页、报告、合盘及 AI 消费方是否使用同一最终事实。不得为单盘结果硬编码。

本轮只更正验证目标、记录代码现状与审计缺口；没有修改业务算法、历史冻结样本或线上结果，未推送。
