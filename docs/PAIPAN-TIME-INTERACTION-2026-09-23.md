# 排盘时间输入专项复查（2026-09-23）

用户提醒三类历史问题：同一时辰具体钟点回填混淆、滚轮关闭后的延迟写入、“今天”把小时当成时辰序号。本轮在第38节触控升级基础上增加实际浏览器回归，并修复残留问题。

## 检查及修复

- 原有 `setHourClockSelection` 使用时辰 value 与 `data-clock` 联合定位；滚轮按原 option 索引选中，保留这套实现。公历 7/8 点、0/23 点及农历 11/12 点连同分钟的草稿恢复已实际测试。
- “今天”原有 `dispatchClock` 正确按 24 小时制的 `data-clock` 定位，没有重新混用时辰序号。但公历、农历年份选项上限仍写死2025，实际2026日期会填空并回落为1990及默认日。两处改为至少覆盖运行时当前年份，保持原1900下限。
- 已复现：滚轮排队提交后立即点“今天”，旧滚轮已被移除，但180ms回调仍读取旧几何位置并覆盖新的小时。现在重建面板、替换日期列前清理待提交回调；任何已脱离当前面板或处于关闭状态的滚轮，不再允许点击/滚动/scrollend回写。
- 关闭时同步提交当前有效滚动一次，再取消其余回调。重开取消220ms关闭计时器，动画帧增加视图版本保护，防止上一轮关闭动作清空新面板。
- 会员本地回填旧入口存在分钟缺失，日期又单独延迟200ms写入。月份change同步生成日期选项，无须再延迟；现在同一轮回填年月日、具体钟点、分钟，并刷新摘要。原先的用户开始编辑后停止自动恢复保护保留。

## 验证

`node tests/touch-controls.browser.cjs` 新增出生时间专项，使用冻结Date与实际运行的动画/计时器、合成数据、静态服务器，不访问生产账号或API。覆盖：

1. 公历四个代表钟点及农历同一时辰双钟点的草稿保存、刷新恢复、分钟保留。
2. 当前年份与24个小时的“今天”按钮映射，包含早晚子时。
3. 滚动中点击“今天”、公农历切换、关闭后旧滚轮事件、关闭立即重开。
4. 会员本地回填与之后用户更改日期，确认没有后续覆盖。
5. 实际表单提交到合成结果目标，检查URL的hour/clock/minute/day完整性。目标保留跨文档视图过渡声明，避免测试空页面制造浏览器过渡错误。
