# 报告往事复核与一致性调整

用户要求整份报告有依据、减少矛盾与重复，不把所有段落都写成待复核；建议通过往事提问帮助判断后续事项。本轮将既有应事校对接入付费报告，增加可追踪的复核补充。不是依靠回答确认未来必然发生，也不是事后改写原判断制造命中。

## 用户流程

1. 报告照常生成、阅读；今年运势部分增加“用过往经历复核报告”，作答可选，不额外创建订单或调用模型。
2. 复用既有最多五题的往事年份问卷，保留候选、依据、具体补充、符合程度、实际年份；支持“都不符合”“记不清”。新题进一步要求对应领域有独立年度触发，不仅因为十神名字而出题。
3. 完成后返回报告，不强制跳进 AI。显示原问题、原候选和用户反馈，以及反馈对后续解释的具体影响。
4. 后续解读只在同领域、同机制、同表现且报告该年已有独立触发时使用支持反馈；否认只降低对应机制的解释优先级，不否定整个领域。正反反馈并存时保留分歧；一次经历仅作补充。无匹配窗口时说明未套用，而非编一个未来事件。
5. 原始报告事实、四柱、旺衰、格局、喜用忌和财富 A 等级不被反馈修改。当前实现是报告中的“复核补充”，不是静默重写原文或重新训练算法。原报告的计算候选和复核后的解释优先级分开保留。

复核补充可随所在报告部分导出；沿用原 PDF 对详情展开、按钮删除、HTML 转义与付费内容控制。单独数据库中的历史报告没有批量改写。

## 程序变化

- 新增 `js/calibration-model.js` 作为浏览器与服务端共用的纯函数模块；`lib/calibration-model.js` 兼容导出新模块。原有选项校验、输入规范化继续使用。未增加数据库表或新接口。
- `buildCalibrationProfile` 按领域、机制、表现聚合；按不同实际年份计数，同一题重复或不同题回填同一年不再升级为重复反馈。不同具体补充不沿用第一条补充当作共同规律。未记清、伪造选项、当前/未来年份不计作已验证往事。
- 修复中文机制名规范化后被抹掉的碰撞问题，例如六冲/六合不再变成相同键。既有被截掉机制名的旧记录不猜测还原，新问题用 v5。已回答问题仍按现有后端升级规则保留。
- 新增 `buildReportReview`，输出历史记录、逐年调整及原候选，不输出命中百分比或未来确认状态。后续窗口直接消费报告已算好的 `row.dynamic`，不运行第二套年度计算或根据反馈改盘。
- `ZhishiCalibration.open` 支持完成后返回报告，游客重新打开沿用已答记录。登录用户复用既有账号校对 API，游客沿用当前设备存储。读取失败显示可重试信息，不阻断原报告。
- 同题快速操作按顺序保存；“完成”等待保存结束，有失败时不能显示完成。本地存储失败也明确提示。对应行为有模拟失败及并发测试，未访问真实账号。
- 服务端与游客 AI 摘要共用校对聚合口径，重复反馈只称为解释线索，不再称为稳定的未来应事规律。

## 报告阅读调整

- 标题、摘要、正文相同内容只显示一次；重复结论的来源仍在详情保留，不再额外产生空标题卡。
- 多个未来年份对应同一复核调整时合并展示，逐年依据仍保留。
- 修复五年摘要在没有突出触发时默认写“平稳延续/只是快慢不同”的矛盾；没有信号不据此确认现实平稳。
- 保留具体的有依据判断，不将全部正文替换为提问；未定段也不靠用户某次确认自动变成确定预言。
