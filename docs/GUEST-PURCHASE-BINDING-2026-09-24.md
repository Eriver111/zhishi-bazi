# 先付款、后注册的购买记录归属

用户本轮目标：当天先购买、随后在同一浏览器注册或登录，账号应显示已购内容，不能因为注册而再次要求购买。本轮不切换支付服务商，不启用支付宝，不做跨设备游客找回。

## 现有缺口

旧 `/api/auth/migrate` 迁移兑换码与本地报告标记，不把游客 `payment_orders`、八字 `report_orders` 关联到账户。登录事件还早于迁移完成，个人中心可能先读出空记录。合盘解锁用 `hp_rpt2`，不等于旧迁移中的 `hepan_rpt`，也没有账号报告入口。

## 本轮实现

- 新微信订单在下单响应中附带独立购买凭证：订单号、48小时有效期、HMAC签名。复用服务端已配置的虎皮椒密钥并使用独立签名上下文；没有新增默认密钥。凭证只保存在当前浏览器，不写进跳转URL、网关参数或公开查单响应。
- 前端在提供付款链接之前保存凭证，存储失败会提示用户处理后重试，不继续跳出页面。最多保留50条，不能为了保存新单静默丢弃旧单。
- 登录/注册调用 `/api/auth/claim-purchases`，服务端验证登录身份和购买凭证，通过数据库事务绑定订单和实际权益。不能只凭订单号、本地已解锁标记或命盘相同认领；已经属于其他账号的订单不能转移。
- `claim_wechat_purchase` 与付款通知共用订单行锁。通知先到时，同时绑定订单及已发放的次数、会员或八字报告；绑定先到时，通知继续按订单上的用户发放权益。合盘权益保存在支付订单中。只改变归属，不重置剩余次数、开始/到期时间、付款时间，也不重复创建权益。
- 购买绑定与旧迁移完成后再通知账号视图。失败保留凭证，个人中心显示“暂未同步/确认中”和重试入口；刷新或从收银台返回后可再同步。迟到响应不清除新账号的本地凭证，保存时保留其他标签页新增的凭证。
- 个人中心显示已绑定八字与合盘报告，合盘有账号权限恢复。只有报告购买时不再在上方显示“暂无购买记录”。读取失败与空列表分开提示。个人中心登录监听仅注册一次，并忽略旧身份/旧渲染请求返回。
- auth30（19个入口）、payment6（三个付款入口）、paywall15。付款方式、定价、算法和报告内容不改。

## 生效条件和边界

1. **先执行 `schema-guest-purchases.sql`，再发布代码。** 此脚本在 `schema-payment-channels.sql` 之后执行，仅新增服务角色可调用的事务函数，可重复执行。2026-09-24 已按用户明确指令在现有生产项目执行并核验，详见交接第49节；配套应用代码仍未提交、推送或部署。
2. 本轮自动绑定覆盖新版下单生成凭证的微信购买：八字、合盘、次数包、会员。注册与付款应在相同站点、相同浏览器存储中完成，清理存储或换浏览器不在本轮找回范围。
3. 48小时覆盖当天以及跨零点支付/注册；不是报告48小时后失效。成功绑定后的账号权益不依赖浏览器凭证，会员仍按原期限计算。
4. 旧订单没有新购买凭证。原兑换码迁移保留，但缺少可靠订单凭证的旧游客报告不会仅凭本地解锁标记自动认领，也没有进行生产历史订单回填。过期或归属冲突保留提示，不能以自动归入新账号冒充恢复成功。
5. 不把支付宝/微信付款人身份猜作网站账号，不新增短信、邮箱找回或实际支付测试。没有访问真实凭据、订单和用户数据。

数据库执行记录：Supabase SQL Editor 返回 `Success. No rows returned`。部署后函数正文去除空白后的MD5为 `55bf2b79681b4a4a02e94c9ad1618e6e`，与本地已测试版本一致；SECURITY DEFINER、固定search_path、仅service_role可调用等8项只读检查全部通过。未调用绑定函数处理实际订单、未进行历史数据回填。仅完成数据库准备并不代表网页功能已上线。
