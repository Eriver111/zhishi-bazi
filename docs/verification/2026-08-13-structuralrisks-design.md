# structuralRisks 结构风险层设计冻结（2026-08-13）

状态：**方向正式批准，暂不实现**。执行顺序不变：P1 冻结 → P1.5 二十盘盲测 → 判断 P1 泛化 → 再决定 P2/结构层顺序。本文档为将来实现时的规格基线。

## 0. 两层模型（工程铁律）

```text
喜神/用神/忌神 = 原局五行总体需求（P1 candidateScores）
结构风险      = 某五行在特定结构、特定岁运条件下可能触发的问题（独立层）
```

**不因存在结构病点就把五行塞回忌神；不动 L3；不把结构风险折算进喜用忌。** 两层同时成立，如 #9：忌神空 + 结构有隐病，不矛盾。

## 1. 实现路径（GPT 定）

不做一套新的命理判断，而是：**现有检测结果标准化 → 补齐必要检测器 → 独立风险评估**。最大限度避免两套系统对同一件事给出不同判断。

现有检测资产的三档状态（Claude 探针实测）：

| 档 | 现状 | 例子 |
|---|---|---|
| ① 已检测但未结构化消费 | breakReasons 枚举、establishConditions ❌ 条目（唯一消费方是 AI 文案层 api/ai-chat.js:113） | #9 伤官克官 |
| ② 规则存在但检测范围不足 | 只有「月令受冲」检测（bazi.js:4014-4016）；财星破印只认天干透财 | #9 子午财印冲（年时遥冲+财藏不透） |
| ③ 完全没有检测能力 | 半合、三合、刑、天干克合等 | #9 卯未半合暗增杀局 |

## 2. 收录边界（GPT 定）

**「没有主动破坏对象的，不叫 structuralRisk」。**

不进：
- 食神格没财 / 建禄财官不显 / 成格条件缺失 / 某十神没透——属「配置不足/成格程度/格局质量」

进（须存在主动冲突关系）：
- 伤官克官 / 财坏印 / 枭夺食 / 官杀混杂达到实际冲突条件 / 比劫争财 / 干支冲克导致关键枢纽受损 / 刑冲直接破坏格局核心节点

## 3. 两层管线（GPT 定）

```text
relationEvents（客观记录，不判风险）
    ↓
structuralRiskEvaluator（问：这个关系到底破坏了什么？）
    ↓
structuralRisks
```

**检测到冲 ≠ structuralRisk 成立**——冲有冲坏/冲开/冲动/冲去忌神/冲掉病神/冲起用神六态，先客观记录再评估，防「全盘检测器上线后四柱热闹一点就满屏风险」。

## 4. 位置权重（GPT 定，第一版不过度数学化）

三级定性：
- **直接/贴邻：强**
- **隔位：中**
- **遥隔：弱**（#9：年干甲 vs 时干庚，遥隔）

再结合：是否透干 / 是否得令 / 是否有根 / 是否被合 / 是否已有制化 → 最终评估。案例够多后再把强中弱转具体分数。

## 5. 救应解耦（GPT 批准）

`jiuYing` 评估逻辑**去掉 isPo 门控**：用于「是否已有救应」评估，**不用于 candidateScores 加分**。同一命局允许：格局总体成立 + 局部有病 + 病有救应（#9 正是：丁印化伤 + 甲己合身，制化使风险降级）。

需扩展：**合绊/合化也算制化**（现 jiuYing 映射只认印/财救应，不认「合」）。

示例输出形态（#9）：
```text
风险：伤官见官
基础严重度：中
位置：遥隔 → 降级
官星：有根
印星：可制伤官 → 有救
甲己合：官星另有牵制/合身关系
最终：低~中风险
```

## 6. 半合处理（GPT 定）

半合检测器可补，但**先入 relationEvents，不入 structuralRisks**。半合是否增力要考虑：中神是否存在 / 月令环境 / 是否得势 / 有无冲破 / 是否透化神——「卯+未→木增强→官杀风险」过度机械。第三轮即使发现半合案例也只收集，不赋风险分。

## 8. #9 黄金样例（GPT 定）

未来期望输出不是「忌神：金、水」，而是：
