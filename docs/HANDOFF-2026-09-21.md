## 1. 当前基线与运行

- 仓库：`zhishi-bazi`，GitHub `Eriver111/zhishi-bazi`，当前分支 `main`。编写时本地 HEAD `30e4ebd`（2026-09-15，`修复排盘时间状态漂移`），工作区原本干净。新窗口先重新核对，不能把此提交号永远当作最新版本。
- Node.js 多页面网站，前端以原生 HTML/CSS/JS 为主。`npm run dev` 调用 `node server.js`；默认 `PORT=3000`。`server.js` 同时负责静态资源和 `/api/*` 路由。依赖见 `package.json`。
- 环境配置由 `server.js` 读取 `.env`，再由 `.env.local` 覆盖。不要将真实环境变量、API Key、管理员密码、数据库数据写入文档或提交。`.env.example` 仅为示例，部分字段可能落后于代码。
- `ecosystem.config.js` 配置 PM2 应用 `zhishi`，端口 3456；`server.js` 包含每 60 秒检查并拉取 GitHub `main` 的逻辑。仓库还含 `vercel.json`。历史对话称在阿里云香港运营，但当前线上机器、版本、域名和 DNS 未在本次交接中核验。**本地提交不等于已上线；推送可能触发自动更新，须先确认。**
- 数据与账号主要依赖 Supabase（`lib/supabase.js`、`schema*.sql`）；存在本地回退存储用于特定开发/恢复场景，不能把它视为可靠生产数据库。反馈持久化对已配置 Supabase 的环境采用失败即关闭策略。

## 3. 命理引擎现状与用户已经明确的判读方向

- `js/bazi.js` 承担四柱、旺衰、格局、从格、喜用忌等核心判定；`js/bazi-chain.js` 承担结构关系、生克链、岁运触发和事件候选，注释明确不应改写冻结的核心旺衰结论。`js/structural.js` 等为辅助层。`docs/current-rules-digest.md` 和 `docs/bazi-system-spec.md` 已过时，不能照其旧分数/行号改代码。
- 用户最担忧算法「逐个例子打补丁后漂移、重复扣分」。应分清原局五行的角色、载体（透干/有根/藏干）、作用对象、成败条件，再给出喜用忌；同一结构因素不能重复计分。单盘反例应提炼机制、跑全类新盘和反例回归，而非仅针对该八字特判。
- 「用神」须说明解决原局的哪一个问题，并标明取用类型（例如格局、扶抑、调候等）；不可把原局里本来重要、但已经足够且不宜再增的五行简单写成「还要补」。也不能用缺什么五行、身弱就补印比、身强就一律忌印等机械规则。
- 食伤旺泄身导致身弱时，比劫可能继续生食伤，不能机械设为首选；印化/制食伤与具体载体需先看。官杀旺、正官与七杀、杀印流通、食神制杀、财破印、土多金埋、水多木漂等均已有讨论和部分实现，须以当前代码与测试为准，勿把会话里的单句判语写成万能法则。
- 先由原局给出喜用忌与有条件的「已到位/不宜再增」等角色，再看某步大运/流年与原局的实际合冲刑害、生克、透藏和年龄阶段，判断方向是否兑现。不能仅因为运中出现某十神就断「事业好」「家人庇护」。大运看趋势、流年看较可能的应期；具体应事须有独立触发与证据，避免装作事件已成事实。
- 「过三关」父母关用宫星同参：年柱代表父母宫/家庭根基，父星偏财、母星正印另看；宫、星、关系远近要分开，不能凭一条规则断亲疏。用户真实反馈优先于系统推断。
- 命理事件账本/审计层用于保存机制证据与冲突，不是让每个事件被当成已发生。用户希望 AI 能更像老师傅：先回答核心问题，再说明证据和不确定性，年龄与场景适配，不讨好、不把坏事强行往好处圆；可以修正推断，但不得为迎合用户擅改四柱等硬事实。

## 4. 合盘、AI、报告的重要边界

- 合盘有甲方/P1 与乙方/P2 两个独立命盘，输入、档案、大运、流年、十神、喜用忌不能互换。`api/ai-chat.js` 当前有身份锁和输出检查：先把男/女、我/他映射到甲乙方，再分别引用 `person1.daYun` / `person2.daYun`；历史 AI 答错时，不许沿错继续编。用户提供过截图：AI 把一方起运、大运顺序说错，连续「纠正」又换了说法。这仍是重点风险，需要真实合盘对话回归，不能只信提示词。
- AI 文本入口 `api/ai-chat.js` 当前代码固定 `deepseek-v4-flash`。视觉服务 `lib/vision-api.js` 默认 `qwen3.7-plus`（阿里云 DashScope），PM2 配置同名模型。模型名、权限、实际线上请求与回退需按目标环境检查，不能仅凭示例配置推断线上结果。
- 命盘校对/反馈的目标是让当前用户的个体解读更准确；并不存在仅凭用户反馈就自动训练/升级基础模型的保证。用户的现实经历是强校验信息，网站生成的父母、婚姻、事业「事件」只是待证推断，不应锁死为事实，免得 AI 与用户争辩。
- 深度报告定位为收费的白话详参，保留支撑结论的关键专业术语，但避免术语堆积、重复段落与凑字数。报告需要能在线保留并下载。财富 A 等级表达原局可达的最高层次而非明确金额承诺；前端最低公开 A6，需结合年龄、大运看现实兑现阶段，不能把少年好运直接说成少年拥有大量资产。现实财富信息可用于复核兑现，不直接改写原局 A 等级。
- AI 提问次数/会员、积分包、深度报告是不同权益，不能让购买积分误解为报告自动解锁；AI 会员不默认包含深度报告。具体价目/支付状态以当前代码和线上配置为准，不在此文件冻结。代码可见 `zpayz` 支付接口；曾讨论过直连微信支付，但未核实已实现，不要擅自切换支付。
