## 2. 开发纪律铁律（新机第一个会话先读这段）

1. **仓库三件套（2026-08-16 新增，最高优先级）**：任何 sha 检查/回归/patch 前，必须先打印 `pwd` + `git rev-parse --show-toplevel` + `sha256sum js/bazi.js`。旧机曾存在过期副本（`bazi-website` 目录=0520b00c，真实仓库是 `bazi-website-ai`=ccaf9ed7）——**测错仓库比算法 bug 更危险**。
2. **sha 铁律**：bazi.js 含 UTF-8 BOM，必须原始字节口径（ReadAllBytes / `git show HEAD:js/bazi.js | sha256sum`），禁用会剥 BOM 的 ReadAllText。两个口径都有效：git blob=LF（2ca3d569）、旧 Windows 工作区=BOM+CRLF（ccaf9ed7）。**新机是 Mac，工作区将天然是 LF**——工作区 sha 会 ≈ git blob 口径而非 CRLF 口径，验证时以 `git show` 口径为准。
3. **冻结纪律**：除非新多盘同机制明确错误，不得改 getPattern / 从格覆盖 / 旺衰 / 用神 / 喜忌 / 救应权重 / 分类层。**层级纪律**：格局成破不得反向污染旺衰（旺衰=基础层、格局=解释层）。用神级联只沿「格局破→用神质量」方向。
4. **消费方契约**：`xiShen/jiShen` = 五行**方向集合**（含弱档成员）；强弱语义查 `elementClassification`（用神/喜神/弱喜/忌神/弱忌）。不得默认 xi 成员全是强喜。此契约注释已入引擎（bazi.js:5008-5010）。
5. **congTrace**（P5-C08 产物）：保留为 debug/evidence 工具（`_p5/p5c08b-m01-anchor.js`），**不进生产用户数据**。未来攻击模式：`candidate=true + realCong=false + fakeCong.checked=false + final=普通格`（当前不存在）。
6. **工作习惯（用户偏好）**：每个改动单独 commit + push origin main；不要只提建议直接动手做；改动简洁不过度设计；歧义时主动反问；批判审查 GPT 裁决（不只执行+汇报）；每步 Write 后 Grep `\d{3}\?` 防占位符污染；服务器禁止直接 `git reset --hard`（生产数据风险）；敏感词替换（算命→命理分析、付费→积分、封建迷信→传统文化）。
7. **控制台编码**：旧机 Windows GBK 下脚本 console 只输出 ASCII、中文写 JSON 文件——新机 Mac UTF-8 无此问题，但脚本习惯保留。
