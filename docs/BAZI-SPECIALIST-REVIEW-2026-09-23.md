# 从弱残余生扶与去官留杀专项证据

2026-09-23，规则记录版本 `zhishi-judgement-v4-20260923`。承接第三批本地源码（见 [第三批复核](BAZI-JUDGEMENT-EVIDENCE-2026-09-22.md)）；Git 基线仍为 main 的 `bc34314`，四批累积工作未提交、未推送。比较用的是本轮修改前保存的 v3 源码，不是 HEAD。

## 本轮解决的问题

1. 从杀、从财、从儿原先在残余生扶检查前返回。现在四类从弱以及假从候选、未通过从弱入口的极弱局均有 `followingReview`，分别列明印星与比劫的柱位、藏干层级、原始根量、实际折损、有效根量与关系引用。同字不同柱位不合并；受损不等于根气消失。
2. 当前取法与纯度认证分开。正式从弱仍有残余生扶时 `reviewRequired=true`，保留现有顺势喜忌，同时明确微根承载待核，不能说绝无根气或已证实真从。没有残余生扶时也不宣称完成了所有从格条件认证。专旺不套从弱复核。候选仍不是正式从格。
3. `gates` 记录当前入口的极弱、日支藏干、印比透干、本气帮扶条件；`powerBasis` 说明原来的天干2/地支本气1只是入口参考量，不是有效根气，也不是制化余力。这些门槛和权重未调整。
4. 去官留杀新增 `controlEvidence`：区分参与合绊的食伤/印星透干、地支制化候选，以及同时给合绊参与者通根的藏干。共享关系按根的唯一 ID 记录，不追加或扣除第二份力量。藏干存在本身不记为完成制化；遥合、争合、已化等前提未通过时，不能靠这些线索绕过前提。
5. 证据传到 `resolvedPattern`、喜用忌报告的 `evidence` 和 AI 上下文。AI 同时接收不得抹去微根、不得将待核写成破格、不得自行反转冻结喜忌的约束。自然语言提示不是所有自由回答都正确的形式保证。
6. 根气和数组使用独立快照；消费方修改证据不会改变统一结算缓存。删除从财、从杀说明中直接承诺财富/层次的文字，从儿说明也不再混入与当前“极弱入口”不一致的泛化断语。

## 规则依据与边界

- [《滴天髓阐微·从象、假从》](https://zh.wikisource.org/zh-hant/滴天髓闡微#十四、假從)讨论生扶存在却不能依靠的情况，因此“有根事实”与“能否自立”需要分别核验。它没有提供本项目使用的数值门槛。
- [《子平真诠·论用神成败救应》](https://www.donglishuzhai.net/chapter/3722.html)区分组合、制化和救应条件，不能仅凭某十神出现就认定救应完成。

以上是传统取法文本，不是现代预测准确率证明。本轮没有创建新的专家标签，没有用程序输出替代独立判读。也没有将所有残余印比局统一改成普通扶抑，或将藏印出现统一认定为杀印成格。

**尚未完成的专项裁决**：不同柱位、层级、受损程度的微根何时足以破从；同一食神合官后是否尚能制杀；暗藏印星是否真正完成生化通路。当前去官留杀仍因独立透干制化的结构限制保持待定，新增的是可审查的具体证据，不应宣传已经完整实现其成格算法。
