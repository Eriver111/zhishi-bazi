# 解锁前后顺序与年龄场景（2026-09-23）

本轮按用户纠正，将第31节“报告后附复核”改成“核验已解锁 → 当前状态 → 往事复核 → 生成报告”。本轮没有修改支付渠道、支付校验、价格或生产数据库。

## 流程

- 现有解锁回调进入 beforeReport；同一账号与命盘只挂起一个流程，重复解锁通知不会重复弹窗或先生成正文。
- 先选择在读、备考/进修、已工作、结束学业后求职/调整、退休或暂不填写，再打开原有最多五题历史问卷。
- 完成等待原有答案保存；明确跳过也能阅读报告。关闭弹窗不会被算作完成，页面保留继续入口。无题、读取错误均提供继续按钮；读取请求有12秒超时，问卷初始化中也保留跳过。
- 结束后读取已保存反馈再生成展示文案；未完成或仍在读取时，不导出半份付费报告。服务器读取失败时回退到按当前状态生成的基础报告，并显示可重试说明。
- 已完成/跳过在本浏览器会话内按账号ID＋命盘记忆；当前状态保存在设备本地并按同样范围隔离。当前状态不跨设备同步，未增加数据库字段。往事答案仍沿用既有账号API/游客本地存储。

## 年龄与实际状态

年龄用于范围，实际状态优先。20岁已结束学业的用户按工作/求职场景；40岁仍在读或备考者保留学习章节。未填写状态时，6—17岁默认考虑学习，成年用户不凭年龄假定仍在读；出生年份未知不编造年龄。

五年逐年推进年龄；未知状态不会把16岁的学校阶段冻结到20岁。显式在读等状态暂按用户当前选择延续，并提示身份变化后修改；没有擅自预测毕业年份。早于状态采集年份的历史报告窗口不套用今天的工作身份。

已结束学业的报告移除学习年度候选、相关领域互动文案和学业章节，PDF同样省略；保留原始结构依据供审计。不把学习信号直接换成事业好坏，不修改原局分数/旺衰/喜忌/格局/A财富分级。历史问卷仍按事件当年的年龄取题，工作后的用户仍可回顾过去升学经历。

## 反馈怎样参与报告

共用模型先限定同领域、同机制和独立年度触发，正反馈还需表现类型一致。匹配后进入该年度主次事件及领域窗口的解释文本；否认/混合反馈不再追加“最值得优先”的肯定措辞。原候选和历史回答仍在复核详情中保留，不把用户告知的往事包装为系统独立预测命中。

本轮不是训练、概率标定或现实准确率验证；有往事支持仍不能确认未来事件必然发生。四柱等冻结事实不随反馈重算。
