## 一、体系基础

### 1.1 流派定位

**主力流派：子平格局法（透干取格派）**，辅以盲派象法做性格/职业解读，兼收《穷通宝鉴》调候作为喜用修正。

选择原因：
- 格局法规则明确、可编程：月令藏干透出→定格，不依赖主观判断
- 盲派象法适合生成自然语言描述（"你像一棵树"）而非数字计算
- 调候是《穷通宝鉴》的核心贡献，与扶抑不冲突，作为修正层叠加

### 1.2 参考古籍与权重

| 古籍 | 使用范围 | 权重 |
|------|---------|------|
| 《耕寸集》（子平真诠原本·王相山精解） | 格局判定主规则 | 最高 |
| 《滴天髓》 | 旺衰话术、日主引文 | 参考 |
| 《三命通会》 | 十神、神煞、合化 | 参考 |
| 《穷通宝鉴》 | 调候修正 | 中等 |
| 《渊海子平》 | 十神定义、口诀 | 参考 |

### 1.3 通用共识 vs 自选观点

**通用共识（跨流派公认）**：
- 年柱以立春为界
- 月柱以节气为界
- 十神定义（生克+阴阳）
- 六冲、六合、三合、三会的地支组合

**自选观点（此系统特有，审查者需注意）**：
- **透干取格只取本气及同五行透干，不取余气中气**（不同于"余气透出亦可定格"派）
- **从格判定：天干有印星不从、藏干本气有印星不从、藏干中气余气有印星仍可从**（本系统自行折中）
- **湿土调候减力：丑辰克水力从-25降至-13**（本系统经验修正，非古籍原话）
- **调候只改喜用列表顺序，不改身强身弱结论**（不同于"调候优先于扶抑"派）
- **子时换日可选，默认开启**（23:00起按次日日柱；关闭后按早晚子时拆分）

### 1.4 流派冲突处理规则

当不同流派结论冲突时，优先级：
1. 透干取格法（耕寸集）> 五行生克法
2. 从格优先于普通扶抑（先判从格，不从再走扶抑）
3. 调候修正喜用列表，但不推翻扶抑的身强身弱结论
4. 湿土/燥土的调候经验修正优先于纯五行生克

### 1.5 简化与近似

以下规则属于简化实现，非完整古籍规则：

| 简化项 | 简化方式 | 影响 |
|--------|---------|------|
| 节气时刻 | 默认近似小时（如寒露≈凌晨3点），未逐年精算 | 节气当天凌晨出生者，月柱可能偏一日 |
| 真太阳时 | 只考虑省份经度+均时差，未考虑海拔高度 | 误差在±5分钟内 |
| 合化判定 | 六合/天干五合**一律按化成功处理** | 不区分合化深浅 |
| 藏干权重 | 只取本气参与旺衰计算，余气不参与 | 中气/余气的细微影响被忽略 |
| 神煞 | 仅保留文昌、学堂、桃花、驿马、羊刃等常用神煞 | 大量古籍神煞未纳入 |
| 调候 | 只处理12个月份的极端寒暖燥湿，不逐日微调 | 同月不同日的细微差异未体现 |

## 二、历法与四柱计算

### 2.1 公历/农历转换

- 来源：寿星万年历简化版，内置于 `js/lunar.js`
- 精度：1900-2100年，误差±1天（简化算法非天文级精度）
- 接口：`LunarCalendar.solarToLunar(year, month, day)` → `{lYear, lMonth, lDay, isLeap}`

### 2.2 年柱切换规则

- **以立春为界**，非正月初一
- 立春前出生→年柱属上一年
- 立春当天需比较精确时刻（立春小时从 `LICHUN_HOUR` 表查，默认中午12点）
- 函数：`getYearPillar(year, month, day, hour)` → `bazi.js:209`

### 2.3 月柱切换规则

- **以12个"节"为界**（立春、惊蛰、清明、立夏、芒种、小暑、立秋、白露、寒露、立冬、大雪、小寒）
- "气"不参与月柱切换（雨水、春分等无影响）
- 函数：`getMonthPillar(year, month, day, hour, clock)` → `bazi.js:247`
- 节气日期来源：`getJieQiDates(year)` → `bazi.js:94`，优先查 `preciseData` 表（1980-2030），无数据时用基准日期微调

### 2.4 节与气的处理

- **节**：用于月柱切换（12个）
- **气**：本系统**不处理**（雨水、春分、谷雨、小满、夏至、大暑、处暑、秋分、霜降、小雪、冬至、大寒仅存在于天文意义，不影响任何计算）

### 2.5 子时换日

- **默认换日**（23:00-24:00按次日日柱）
- “子时换日”默认勾选；用户关闭后改用早晚子时拆分口径。开启时：
  - 日柱按次日计算
  - 时柱同步按次日重算
  - **月柱不受影响**（仍以实际出生日为准）
- 函数：`result.js:1284-1298`

### 2.6 真太阳时

- 输入：省份（或城市）、出生钟点、分钟
- 计算公式：`真太阳时 = 钟表时间 + (当地经度-120°)×4分钟 + 均时差(EOT)`
- 经度数据：`PROVINCE_LNG` 和 `CITY_LNG`（省份/城市近似经度）
- 均时差（EOT）：标准天文公式，基于儒略日计算
- 函数：`getTrueSolarHour(hour, province, year, month, day, minute, clock)` → `bazi.js:3637`
- **不禁用夏令时处理**（中国夏令时仅1986-1991，系统未特殊处理，那六年的夏天差1小时）
- 输出：调整后的时辰索引（0=子, 1=丑...11=亥）

### 2.7 柱位计算公式

| 柱 | 公式 | 基准 |
|----|------|------|
| 年柱 | `yearGanIdx = (year-4)%10`, `yearZhiIdx = (year-4)%12` | 1984=甲子年 |
| 月柱 | 五虎遁：年干定正月天干起点 + 月支索引 | 《五虎遁》口诀 |
| 日柱 | Date.UTC偏移法，基准1900-01-31=甲辰日 | 公历公式 |
| 时柱 | 五鼠遁：日干定时辰天干起点 + 时辰索引 | 《五鼠遁》口诀 |

函数：`calculateBaZi(year, month, day, hour, gender, clock)` → `bazi.js:477`

### 2.8 大运顺逆

- 阳年（甲丙戊庚壬）男→顺排，女→逆排
- 阴年（乙丁己辛癸）男→**逆排**，女→顺排
- 函数：`calculateDaYun()` → `bazi.js:616`

### 2.9 起运岁数

- 顺排：从出生日往前数到下一个节的**天数÷3 = 起运岁数**
- 逆排：从出生日往后数到上一个节的**天数÷3 = 起运岁数**
- 余天折合：1天=4个月，1时辰(2小时)=10天
- **已做归一化**：满30天进位1月，满12月进位1年（防止出现"15个月"这种显示）
- 函数：`calculateDaYun()` → `bazi.js:664-684`

### 2.10 四柱直接输入 vs 日期排盘

- 日期排盘模式：完整走历法转换→真太阳时→四柱计算→大运（全链路）
- 四柱直接输入（合盘功能中）：**跳过历法、节气、真太阳时**，直接使用用户提供的干支
- 直接输入时：年柱不验证立春、月柱不验证节气

### 2.11 已知边界误差

1. **节气表1980年前精度差**：使用基准日期+闰年微调，最大误差可达±2天
2. **节气小时为近似值**：5个主要节气有逐年的小时表（LICHUN_HOUR等），其余7个用默认小时（jqDefHours），非精确天文时刻
3. **中国夏令时未处理**：1986-1991年夏天出生的，真太阳时可能差1小时
4. **子时换日+跨月**：假设出生在1月31日23点且开启子时换日，日柱按2月1日算，但月柱按1月算（既不改月份也不改年份），此逻辑是否正确未经审查
5. **2030年后节气**：完全依赖基准偏移公式，未逐日验证

### 3.10 拱合、暗合、夹拱

- **拱合/夹拱：未实现**
- 暗合：仅今年运势的流年分析中使用（"流年与原局暗合"），不参与旺衰计算

### 3.11 同柱/邻柱/隔柱权重

- **有区分**：邻柱的地支合冲刑害权重（±2-3）> 隔柱（±1-2）
- 跨柱六合/冲/刑已新增检测（之前遗漏，现已补全）
- 同柱关系主要体现在：月干+月支的复合格局检测（如"杀印相生"）

### 3.12 合而不化

- **未实现**——系统对合化一律按"化成功"处理
- 唯一的"半化"处理：湿土调候修正（丑辰克水力减半，因为湿土不完全克水）

### 3.13 刑冲合害优先级

当同一地支同时出现多种关系时，系统按以下顺序依次计分：
1. 六冲（最优先，影响根气）
2. 三合/三会（改写五行）
3. 六合（改写五行，但弱于三合）
4. 刑（扣分）
5. 害（扣分）

所有扣分是**累加的**，不做互斥判断（"如果已经冲了就不算害"这类逻辑不存在）。

## 四、旺衰和身强身弱

### 4.1 判定流程总览

```
calcDayMasterStrength(bazi)
  → ①得令（月令±30/20/-15/-10/-25，湿土修正-13）
  → ②得地（日支±12/8/-10/-6/-7）
  → ③得势（四干各±6/4/-4/-3/-5）
  → ④藏干本气（各±3/2/-2/-1/-2，只取本气）
  → ⑤五行过耗修正（月令五行过旺，扣分）
  → ⑥调候（寒暖燥湿±5/-8/-12等）
  → ⑦天干合化修正（五合化气后调整）
  → ⑧地支关系修正（冲合刑害三合三会全部算过）
  → ⑨跨柱关系修正（六合、冲、刑→新增）
  → ⑩日支合化得地重构（日支被合→五行变→得地分重算）
  → 输出分数→映射到level
```

条件（全部同时满足）：
1. `level === '极弱'`（分数<30）
2. `!hasDayRoot`（日支藏干无日主之根或无印星之根，**只查本气**）
3. `!hasGanHelp`（天干无印星或无比劫帮身）
4. `!hasZhiHelp`（地支**本气**无印星或无帮身，中气余气不算）

从格类型判定：
- `kePower >= 6 && kePower >= dgPower*2` → 从杀格
- `caiPower >= 6 && caiPower >= dgPower*2` → 从财格
- `shiPower >= 6 && shiPower >= dgPower*2` → 从儿格
- `keXieHaoTotal >= shengFuTotal*2` → 假从势格

函数：`getCongGe(bazi)` → `bazi.js:4142`

#### 从强格

条件（全部同时满足）：
1. `level === '极强'`（分数≥85）
2. `kePower <= 1 && shiPower <= 1`
3. `!dayZhiIsKeXie`（日支不是克泄耗五行）
4. `!hasCangKeXie`（**藏干**里也没有克泄耗五行）

函数：`getCongGe(bazi)` → `bazi.js:4183-4217`

### 4.5 真从/假从区分

- **真从**：满足所有从格条件，且 `hasGanHelp=false && hasZhiHelp=false`（天干和藏干本气均无帮身）
- **假从**：满足大部分从格条件，但藏干**中气/余气**有帮身（本系统认为中余气深藏不透，不破从格）
- 本系统不单独输出"真从/假从"标签，统一输出从格名

### 4.6 专旺格/化气格

- **未实现**（专旺=从强格取代，化气未做）

### 4.7 临界值处理

- 40分是中和下限，30分是偏弱下限。30-40之间的命盘称为"偏弱"
- 60分是偏强下限。40-60是中和
- **没有防抖/平滑处理**——41分和39分结论不同，即使差1分也可能从中和跳到偏弱
- 调候修正后分数可能变化±5-18，可能导致身强/身弱反转（已知风险）

## 五、格局判定

### 5.1 判定方法

**《耕寸集》透干取格法**，规则：
1. 取月支藏干（本气→中气→余气），依次检查是否透出在四柱任意天干
2. 第一个透出的藏干对应的十神即为格局
3. 只有**与本气同五行**的透干才取为格（余气透干不取格）
4. 若都不透，取本气对应的十神
5. 同五行的天干（但不同字）若存在，也视为透干（如寅月本气甲，天干有乙→同木→取本气十神）

函数：`getPattern(bazi)` → `bazi.js:3722`

### 5.2 支持的格局

#### 单格局（月支本气定向）

| 格局 | 条件 | 十神 |
|------|------|------|
| 正官格 | 月支本气十神=正官 | 正官 |
| 七杀格 | =七杀 | 七杀 |
| 正财格 | =正财 | 正财 |
| 偏财格 | =偏财 | 偏财 |
| 正印格 | =正印 | 正印 |
| 偏印格 | =偏印 | 偏印 |
| 食神格 | =食神 | 食神 |
| 伤官格 | =伤官 | 伤官 |
| 建禄格 | 月支五行与日主同五行 | 比肩(兜底,月令取格fallback) |
| 羊刃格 | 阳日主见帝旺月支 | —(未单独实现,用比肩格兜底) |

#### 同柱复合格局（月干+月支组合）

| 杀印相生格 | 月干印 + 月支七杀 |

### 5.3 破格条件

- **无破格检测**——系统只判定"是什么格"，不判定"这个格是不是破了"
- 合化导致的格局变化由复合格局间接处理（如"财生官格"意味着财被官化了）

### 5.4 多格局共存

- **不支持兼格**——复合格局命中即返回，单格局只返回一个
- 多个条件同时满足时：复合格局优先于透干取格优先于月令取格

## 六、喜用神与忌神

### 6.1 喜用忌分类

本系统使用**三层模型**：喜神、用神、忌神

| 概念 | 定义 | 系统实现 |
|------|------|---------|
| 用神 | **最关键的五行**（首位） | `yongShen[0]` |
| 喜神 | **有利的五行**（含用神） | `xiShen[]` |
| 忌神 | **不利的五行** | `jiShen[]` |
| 调候神 | 寒暖燥湿修正 | 代码内嵌，注入喜/用列表 |
| 仇神 | (未单独输出) | — |
| 闲神 | (未单独输出) | — |

### 6.2 喜用判定规则

#### 从格优先
- 从格→喜用忌完全反转（从杀格喜财官杀，忌印比）
- 函数：`getYongJi(bazi)` → `bazi.js:3950-3963`

#### 普通扶抑
```javascript
if (极强/偏强) → 喜克泄耗(官杀、食伤、财) + 忌生扶(印、比)
else if (极弱/偏弱) → 喜生扶(印、比) + 忌克泄耗(官杀、食伤、财)
else (中和) → 按分数倾向：<50分喜生扶，>=50分喜克泄耗
```
函数：`bazi.js:3965-3995`

#### 调候修正
- 在扶抑结果上叠加调候需求：符合条件的五行从忌神中移出→加入喜神列表
- 调候**不改变**身强身弱结论，只修改喜用列表
- 覆盖12种月令×日主的极端寒暖燥湿
- 函数：`bazi.js:3998-4066`

#### 格局微调
- 在reasoning中加一句提示（如"官多变鬼，需印星转化"），**不改喜用列表**
- 函数：`bazi.js:4058-4079`

### 6.3 冲突解决

1. **从格完全覆盖扶抑**（先判从格，从格命中则直接返回）
2. **调候修正扶抑的喜用列表**（调候五行优先，从忌神中移除，加入喜神）
3. **格局只在reasoning提示，不改喜用**

### 6.4 "缺什么≠需要什么"

- 系统**不会**因为"全局无木"就自动推荐木
- 喜用完全基于扶抑+调候规则，不基于五行平衡
- 例如：全局无木的身强命，不会推荐木（因为木是生扶的印/比劫，是忌神）

### 6.5 输出字段

```javascript
{ dayMasterLevel: '偏强',      // 日主等级
  dayMasterScore: 68,          // 旺衰分数
  xiShen: ['木','火','土'],   // 喜神列表
  yongShen: ['木','火'],       // 用神列表（=喜神前N项）
  jiShen: ['金','水'],        // 忌神列表
  reasoning: '日主偏强……',    // 推理文本
  congGe: null                 // 从格信息(若不是从格则为null)
}
```

## 七、大运和流年

### 7.1 大运排列

- 顺排：月柱干支往后轮推8步（每步10年）
- 逆排：月柱干支往前轮推8步
- 函数：`calculateDaYun()` → `bazi.js:686-711`

### 7.2 起运时间

- 起运年龄 = 出生日到最近一个节的**天数 ÷ 3**
- 交运年份 = 出生年份 + 起运年龄（浮点数）
- 显示为"X岁起运"，起运岁数已归一化（天→月→年进位）
- 函数：`calculateDaYun()` → `bazi.js:663-684`

### 7.3 大运参与原局的方式

- 大运天干/地支的五行**参与原局的喜忌判断**（在`yongJi`参数中传递）
- 大运与原局的合冲刑害**在旺衰计算中体现**（跨柱六合/冲/刑检测）
- 今年运势分析中：**大运天干+流年天干+原局三者联动**

### 7.4 大运×流年×原局三层作用

在 `analyzeThisYear()` 中（`bazi.js:3102`）：
1. 先计算当前大运
2. 流年与原局做冲合检测
3. 大运与流年做天干生克检测
4. 三合/刑/破/暗合同时查原局+大运+流年三者的组合
5. 大运信息+大运警告注入返回结果
6. `riskLevel` 根据喜忌调整（喜用年-1，忌神年+1）

### 7.5 天克地冲/岁运并临/伏吟/反吟

- **天克地冲**：天干相克+地支相冲同时出现→追加警告文本
- **岁运并临**：未单独处理（天干十神相同的警告覆盖了此场景）
- **伏吟**：未实现
- **反吟**：未实现

### 7.6 喜忌到位≠一定吉

- 系统对"喜用年"给出利好标签，但对"忌神年"不绝对判凶——会提示"适合修炼内功"
- 不管忌神年还是喜用年，系统都会给出"需要回避的"和"今年可能的机会"两段描述

## 八、AI 铁律和上下文

### 8.1 JS 传给 AI 的完整数据

在 `api/ai-chat.js` → `buildChartContext(chartData)` 函数中构建。

**八字基础数据**（事实类，AI 不可修改）：
- `year/month/day/hour`: 干支、五行、十神、藏干、纳音
- `dayMaster`: 日干、五行
- `shenSha`: 神煞列表

**算法判断数据**（AI 必须优先相信）：
- `dayMasterStrength`: 身强身弱标签+分数
- `pattern`: 格局名+描述+判定来源
- `xiShen/yongShen/jiShen`: 喜用忌列表
- `daYun`: 大运列表（干支+起止年+十神）
- `liuNian`: 流年列表

**当前时间锚定**（AI 基准）：
- `currentYear`: 当前年份（干支）
- `currentMonth`: 当前流月（干支）

### 8.2 AI 铁律（系统提示词摘要）

位置：`api/ai-chat.js` → `SYSTEM_PROMPT`

核心规则：
1. **禁止泄露后端信息**（模型名、API端点等）
2. **若chartData已提供预计算结论，必须逐字引用**——不要用自己的判断覆盖
3. **不能根据常识重新判断身强/格局/喜忌**
4. **没有把握时必须明确告知**，不能强行编造
5. **涉及未来预测必须注明"命理分析仅供参考"**
6. **禁止预断寿命、禁止制造恐慌、禁止替代医疗建议**

### 8.3 AI 不可覆盖的字段

- 身强身弱（`dayMasterStrength.level`）
- 格局判定（`pattern.name`）
- 喜用忌神（`xiShen/yongShen/jiShen`）
- 大运排列（`daYun.list[]`）

### 8.4 AI 可以发挥的领域

- 用通俗语言解释命理概念
- 结合多个字段生成连贯叙述
- 补充未在 chartData 中的古籍引文（但不能与 chartData 矛盾）
- 根据喜用忌给出生活建议

### 8.5 字段可能冲突的场景

1. **AI 有时会混淆年柱和当前流年**（已修复：系统提示词注入当前年份）
2. **深度报告模板和 AI 对话可能给出不同格局**（已修复：pro-analysis.js统一调getPattern）
3. **中和命盘的喜忌没有绝对正确方向**（系统倾向偏弱生扶）

## 九、深度报告逻辑

### 9.1 生成方式

- **规则拼接**（不是再次调用AI）
- 每个付费 section（今年运势/婚姻/财运/学业/流年）由 JS 函数独立生成HTML
- 调用了白化、财运分析、学业分析等算法函数，基于八字数据做规则化输出

### 9.2 使用的专业字段

| Section | 使用的字段 |
|---------|-----------|
| 今年运势 | `yongJi.dayMasterLevel`、流年干支、十神 |
| 婚姻 | `analyzePei()` 输出（夫妻宫藏干十神+配偶星+晚婚信号） |
| 财运 | `analyzeWealth()` 输出（财星统计+旺衰+方向+城市） |

| 五年流年 | `analyzeFortune()` 输出（大运+逐流年） |

### 9.3 不用喜用忌的 Section

- **日主性格**：只用日干+藏干+五行数量
- **四柱分析**：只用十神+合冲刑害（不依赖旺衰）
- **大运列表**：纯排列展示，不做解读

### 9.4 报告与 AI 的可能冲突

1. **深度报告的格局判定曾与 AI 不同**：pro-analysis.js 自建了简化判定→已修复为统一调用 `getPattern()`
2. **深度报告的喜用忌与 AI 一致**：两者都调用 `getYongJi()`
3. **身强身弱显示**：pro-analysis.js 调用 `calcDayMasterStrength()`，与 result.js 一致

### 9.5 概率描述 vs 确定结论

- **确定结论**：四柱排列、十神、格局名、大运列表
- **算法判断**（非绝对）：身强身弱分数、喜用忌神、财运量级、学业等级
- **模板文案**：婚姻对象特征、样貌描述（基于十神类型的固定模板）

### 9.6 报告生成路径

`js/result.js:render(data)` → 逐个调用各 section 的 render/analyze 函数 → 注入 DOM

2. 月令合化反扣的-18/-10/-8分档（经验值）
3. 从格判定中"藏干本气有印不从，中余气有印可从"的折中逻辑
4. 子时换日的跨月边界处理

### 11.4 可能矛盾的字段

1. 深度报告的"格局"输出在两个位置（result.js 和 pro-analysis.js），已统一但需持续监控
2. 喜用列表可能因调候修正而与纯扶抑结论不同——这是设计意图，但可能被误解为 bug

### 11.5 临界盘易出错

1. 40分和41分——差1分从中和跳到偏强
2. 节气当天出生的——真太阳时可能跨日→月柱不同
3. 子时出生+跨月——可能日柱变了但月柱没变（子时换日bug已修但需验证）
4. 寒露/立冬/立秋/立夏/立春/小寒的小时精度影响月柱

### 11.6 需重点复核的函数

1. `calcDayMasterStrength()` — 167行，全站核心
2. `getCongGe()` — 从格门槛，易出现假阳/假阴
3. `getMonthPillar()` — 节气比较+子时边界
4. `getTrueSolarHour()` — 真太阳时+夏令时盲区
5. `analyzeThisYear()` — 大运+流年+原局三层互动
