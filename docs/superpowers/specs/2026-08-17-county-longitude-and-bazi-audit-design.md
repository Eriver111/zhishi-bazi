# 县级真太阳时与八字十盘审计设计

日期：2026-08-17  
状态：用户已确认设计，等待书面规格复核  
适用范围：八字排盘出生地经度解析、真太阳时展示、旺衰喜用忌格局的分批审计  

## 1. 目标

本次工作解决两个已确认事项：

1. 为当前出生地选择器内大陆及港澳台全部 2,901 个县级条目补齐县级行政中心经度，避免小县城静默使用市级或省级经度。
2. 建立每轮 10 个全新案例的盲审流程，独立复核网站给出的旺衰、喜神、用神、忌神和格局；发现差异后先提交证据，未经用户确认不得修改命理引擎。

观手 AI 在 iPhone Safari 上已恢复可用，当前无法稳定复现，明确排除在本轮代码修改之外。

## 2. 非目标与约束

1. 不采集 GPS，不调用在线地图，不增加详细地址、乡镇、村或手动经度输入。
2. 县级经度表示县级行政中心经度，不宣称是具体出生地点的精确坐标。
3. 不因一次或一批审计差异直接修改旺衰、喜用忌或格局规则。
4. 不用网站输出反向影响人工盲审结论。
5. 不重复使用已经进入正式审计批次的案例。
6. 不在本轮修改观手 AI；若 Safari 问题复发，另行保留时间、页面阶段、请求状态和控制台信息后再诊断。

## 3. 县级经度数据

### 3.1 数据范围

经度表必须逐项覆盖 `js/region.js` 当前提供的 2,901 个县级选择项，包括大陆、香港、澳门和台湾地区。覆盖统计以完整路径为准，不以县名去重后的数量为准。

每条记录至少包含：

```js
{
  key: '河北省|石家庄市|长安区',
  longitude: 114.54
}
```

经度保留足以支撑分钟级太阳时换算的精度。数据文件包含明确版本号和来源说明，后续更换数据时能够追查排盘变化原因。

### 3.2 唯一键

地点唯一键固定为：

```text
省级名称|市级名称|县级名称
```

禁止只按县名查找。现有列表存在 38 类重名县区，例如北京与长春的“朝阳区”、北京与南通的“通州区”；完整路径是防止串位的必要条件。

### 3.3 数据维护规则

1. 县级选择器新增、删除或改名时，完整率测试必须同步失败，直到经度表更新。
2. 经度必须是有限数值并处于有效范围 `[-180, 180]`；本数据集另做中国区域合理性检查。
3. 同一完整路径不得出现重复记录。
4. 数据生成或整理过程可以使用脚本，但运行时必须读取仓库内冻结的数据，不依赖网络。

## 4. 地点解析契约

真太阳时只通过一个统一地点解析入口取得经度，禁止表单、结果页和历史报告各自维护不同查找逻辑。

解析输入：

```js
{
  province: '河北省',
  city: '石家庄市',
  district: '长安区'
}
```

解析输出至少包括：

```js
{
  longitude: 114.54,
  level: 'county',
  source: 'county-centroid-v1',
  matchedKey: '河北省|石家庄市|长安区',
  estimated: false
}
```

允许的状态为：

1. `county`：省、市、县完整路径直接匹配。
2. `county_alias`：历史行政区名称经受控别名映射后匹配到当前县级记录。
3. `city_fallback`：仅供旧订单或异常旧数据使用，县级无法匹配时按市级估算。
4. `province_fallback`：仅供更残缺的历史数据使用，市级也无法匹配时按省级估算。
5. `default_fallback`：历史数据连省级也无法识别时使用标准经度 120°E，并明确标为最低可信降级。

新表单从当前三级列表完成选择后必须得到 `county`。任何降级都属于数据完整性错误，不允许静默提交为精确县级结果。

## 5. 真太阳时数据流与展示

数据流固定为：

```text
省 / 市 / 县选择
  -> 完整路径解析
  -> 县级行政中心经度
  -> 经度时差 + 均时差
  -> 真太阳时分钟与日期偏移
  -> 时辰及四柱
  -> 结果页披露经度来源
```

表单跳转、结果页重算和历史订单回放必须携带同一组省、市、县字段，并调用同一解析器。不得只传县名，也不得由结果页再次使用另一份经度表。

用户可见文案：

- 县级命中：`按长安区县级行政中心经度 114.54°E 校正`。
- 别名命中：同时说明旧名称已映射到当前县级行政区。
- 降级：明确显示 `县级经度未匹配，当前按石家庄市经度估算`，不得再笼统显示“经度已校正”。

经度来源只说明计算基准，不夸大为具体出生地址精度。

## 6. 兼容与异常处理

1. 新订单：三级地点选择完整时必须县级命中，否则阻止生成并提示重新选择出生地。
2. 历史订单：保留旧名称兼容；优先使用受控别名，其次才按市、省、120°E 降级。
3. 四柱直排：继续不使用出生地和真太阳时。
4. 缺少地点：按现有业务兼容要求处理，但页面必须披露没有使用县级经度。
5. 数据版本升级：不偷偷覆盖历史输入；报告身份与缓存应能区分影响四柱的经度数据版本，避免旧缓存冒充新排盘。

## 7. 十盘盲审流程

### 7.1 案例选择

每轮建立 10 个固定且未使用过的案例。不是无约束随机，而是分层覆盖以下类型：

1. 明确身强。
2. 明确身弱。
3. 从格疑似或从格边界。
4. 专旺疑似或专旺边界。
5. 调候优先案例。
6. 格局与常规旺衰结论可能冲突的案例。
7. 月令、透干、根气或制化存在临界判断的案例。

每轮应兼顾季节、日主、性别及地域差异，并确保县级真太阳时已经稳定计算，避免错误时柱污染审计。

### 7.2 冻结与对比

每个案例按以下顺序处理：

1. 冻结出生年月日时、性别、完整出生地、经度数据版本和最终四柱。
2. 在不读取网站结论的前提下，独立记录旺衰、喜神、用神、忌神、格局及逐条依据。
3. 冻结人工判断及其版本。
4. 运行网站并保存网站事实层和用户可见结论。
5. 逐字段对比，不允许审计后反向改写人工基准来制造一致。

### 7.3 差异分类

差异只允许归入以下类别：

1. `明确程序错误`：代码与自身已冻结规则、基本数据或事实链矛盾。
2. `证据不足`：网站或人工结论缺少足够事实支持，暂时不能下确定结论。
3. `流派口径差异`：存在可解释的不同命理口径，不自动视为程序缺陷。
4. `数据或排盘问题`：历法、地点、真太阳时、时柱或输入链不一致，必须先解决输入事实，不能归咎于命理规则。

## 8. 审批门槛与循环

每轮 10 盘结束后必须暂停，向用户提交：

1. 十盘输入与人工结论摘要。
2. 网站输出逐项对照。
3. 问题清单与差异分类。
4. 每个问题的命理依据、代码依据和影响范围。
5. 建议修正方式及可能影响的既有案例。

即使属于明确程序错误，也不得在本轮审计中直接修改。只有用户明确确认可修的问题才能进入实现。

获准修正后：

```text
为获准问题补失败测试
  -> 最小修复
  -> 回归原 10 盘及全量测试
  -> 冻结修复版本
  -> 选择完全不同的新 10 盘
  -> 开始下一轮盲审
```

未经批准的问题继续保留在审计记录中，不能删除、改名掩盖或混入后续修复。

## 9. 测试与验收

### 9.1 经度数据测试

1. `js/region.js` 的 2,901 个县级路径全部有且仅有一条经度记录，覆盖率 100%。
2. 经度表没有孤立路径、重复键、非数值或越界值。
3. 38 类重名县区按完整路径得到各自正确经度。
4. 东西部极值县区不会错误退回 120°E。
5. 港澳台当前列表全部覆盖。

### 9.2 真太阳时测试

1. 固定日期和钟点下，县级经度参与经度时差与均时差计算。
2. 选择不同经度的同名县区会得到不同且可验证的真太阳时。
3. 覆盖真太阳时跨时辰、跨午夜及日期偏移边界。
4. 表单、结果页、深度报告与历史订单回放使用相同解析结果。
5. 新选择缺失县级数据时不能静默降级。
6. 历史旧地名能够别名匹配或明确降级。

### 9.3 页面验收

在桌面与 iPhone Safari 尺寸检查：

1. 县级命中与降级文案准确。
2. 经度、真太阳时、时辰和最终四柱前后一致。
3. 长县名及说明不会横向溢出。
4. 控制台无新增错误。

### 9.4 审计验收

1. 每批恰好 10 盘，案例 ID 跨批次不重复。
2. 人工判断的冻结时间早于网站对比结果。
3. 每项结论都保留可核对依据。
4. 发现差异后能够证明流程在修改引擎前暂停。
5. 用户批准的修复有失败测试、原批次回归和全量回归证据。
