# 八字与紫微出生时间统一及四柱录入优化设计

## 目标

1. 紫微斗数支持公历、农历两种出生信息录入。
2. 八字与紫微复用同一套出生时间归一化规则，避免真太阳时、跨日和时辰结果不一致。
3. 八字保留现有“子时换日”规则并默认开启，不改变已经验证的日柱偏移算法。
4. 优化八字“四柱”录入模式的视觉层级和手机端体验，不改变直接四柱的计算、反查和结果身份规则。

## 不在范围内

- 紫微不支持直接四柱录入。
- 不更换紫微安星、宫位、四化和大限计算库。
- 不修改支付、积分、订单、报告解锁或用户存档逻辑。
- 不改动八字直接四柱模式已经验证的专业计算结果。

## 统一计算架构

新增一个独立的出生时间归一化边界，由八字个人排盘和紫微排盘共同调用。该边界只负责：

- 校验公历日期与钟表时间；
- 将农历输入转换为公历日期；
- 根据统一的省、市、区县经度数据计算真太阳时；
- 计算经度时差和均时差；
- 处理真太阳时跨公历日期；
- 将最终钟表时间映射为十二时辰；
- 判定子时及日柱换日偏移；
- 返回供八字与紫微分别消费的标准结果。

标准结果至少包含：

- 原始公历日期与时间；
- 农历转公历后的日期（如适用）；
- 真太阳时日期、小时、分钟；
- 十二时辰索引；
- 是否子时；
- 八字日柱偏移；
- 紫微所需的早子时或晚子时时辰索引；
- 经度、经度差分钟、均时差分钟和跨日量；
- 可供前端展示的排盘依据摘要。

八字继续使用现有八字核心计算四柱。紫微继续使用现有 `iztro` 计算命宫、身宫、星曜和四化，但传入的日期、时辰及晚子时标记必须来自统一归一化结果，不再在紫微页面内维护第二套真太阳时公式和经度表。

## 公历与农历录入

### 八字

保留现有“公历 / 农历 / 四柱”三种模式。公历和农历进入统一出生时间边界；四柱模式仍把用户输入的四柱视为最终命盘，不参与出生地、真太阳时或晚子时换日计算。

### 紫微

新增“公历 / 农历”两个模式，不提供四柱模式。

- 公历模式直接提交公历年月日和钟表时间。
- 农历模式复用八字现有农历日期选择和农历转公历能力，支持闰月。
- 两种模式共享性别、出生地、真太阳时和晚子时换日设置。
- 农历转换完成后必须进入同一出生时间归一化边界，禁止紫微页面再次独立校正。

## 子时换日规则

保留现有页面名称“子时换日”，进入排盘页时默认开启；用户关闭后采用早晚子时拆分口径。

判断顺序：

1. 先按用户的钟表时间和出生地计算真太阳时。
2. 如真太阳时发生日期跨越，先更新最终公历日期。
3. 开关开启且最终校正时间处于晚子时（23:00—23:59）时，令 `dayPillarOffset = 1`；早子时（00:00—00:59）的公历日期本身已经进入次日，不再额外偏移。
4. 日柱继续通过 `day + dayPillarOffset` 计算，不修改 `calculateBaZi` 和 `getDayPillar` 的现有算法。
5. 最终校正后不是子时的人，即使开关保持开启，`dayPillarOffset` 仍为 `0`，排盘不受影响。

采用子初换日口径：默认开启后，晚子时按次日日柱，早子时按已经进入次日的公历日期取日柱，二者属于同一个命理日。关闭后采用早晚子时拆分，23:00—23:59仍按当日日柱。丑时至亥时均不受该开关影响。

紫微需要继续区分 `iztro` 的早子时和晚子时专用索引，不把二者合并成同一个紫微时辰参数；页面开关与八字共用同一默认状态和标准化入口，但不得绕过紫微库自身的子时安星规则。

## 排盘依据展示

八字和紫微在提交或结果区域展示同源的简短依据，例如：

- `真太阳时 22:47 · 亥时`
- `真太阳时 23:18 · 子时，已启用子时换日`
- `未启用真太阳时 · 北京时间 08:30 · 辰时`

该信息只用于核验，不代替专业结果，也不重复显示两套四柱。

## 四柱录入界面

四柱模式只改 DOM 结构和样式，不改变字段 ID、查询参数、校验、反查或结果页逻辑。

### 视觉适配

- 复用当前网站的宣纸暖白、朱砂、松石绿、边框、字体、圆角和按钮变量。
- 不照搬视觉草图中的额外品牌印章、手机外壳或装饰性山水。
- 与公历、农历模式保持相同卡片宽度和页面节奏。
- 四柱按年、月、日、时横向排列，日柱使用克制的朱砂边框或文字强调。
- 每柱包含柱名、天干选择格、地支选择格及就地错误提示。
- 选择格保持原生或无障碍可操作的 `select`，视觉上呈现为命盘方格。

### 响应式

- 桌面端保持四列等宽。
- 手机端仍保持四列，不变成两行两列。
- 选择格高度不低于 44px，文字不得截断，页面不得横向溢出。
- 极窄屏通过缩小列间距、内边距和辅助文字解决，不缩小主要点击区域。
- 性别选择、主按钮和匹配日期结果在手机端使用整行布局。

### 匹配结果

- 保留近两百年四柱反查逻辑与“继续使用基础命盘”的现有能力。
- 匹配候选使用清晰的日期、时辰和时间范围列表。
- 不为直接四柱模式制造出生地、真太阳时或晚子时参数。

## 兼容与回退

- 原有八字结果页查询参数继续兼容；缺少新字段时采用当前站点默认规则。
- 紫微旧入口仍可直接使用公历参数起盘。
- 统一模块异常时不得静默生成盘，应在输入页显示可理解的校验错误。
- 四柱视觉样式应能通过删除独立样式块回退，不影响计算代码。

## 测试标准

### 时间边界

- 22:59、23:00、23:59、00:00、00:59、01:00。
- 子时换日开启和关闭。
- 真太阳时将北京时间推入或推出子时。
- 真太阳时跨前一日或后一日。
- 闰年、月末、年末和节气交界。

### 历法

- 公历与对应农历输入得到相同标准公历日期。
- 农历闰月与非闰月正确区分。
- 无效日期在起盘前被拒绝。

### 跨功能一致性

同一份公历或农历出生资料，在八字和紫微页面必须得到一致的：

- 最终真太阳时日期；
- 最终小时与分钟；
- 十二时辰；
- 子时判定及日柱偏移；
- 排盘依据摘要。

八字四柱与紫微页面展示的四柱依据不得因页面自行重复换算而冲突。

### 四柱界面

- 所有既有字段 ID 和查询参数保持不变。
- 桌面与手机均为四列。
- 320px 宽度无横向溢出。
- 选择器触控高度至少 44px。
- 反查、候选选择、无匹配继续排盘和错误提示行为保持通过。
