## 一、触发案例与根因

- 触发盘：乙酉 戊寅 丁丑 癸卯（寅藏甲丙戊）。站点文案「月支寅藏乙，透于年柱(同木透) → 正印」——乙是年干透干，非寅藏干，且乙=偏印与「→ 正印」自相矛盾。
- 根因（bazi.js 同五行兜底分支 4276-4285 与 source 模板 4378-4382 语义错配）：兜底分支把**外透干**存入 matchedGan，source 模板却按「藏X」输出，把透干写成月支所藏。
- 精确匹配分支无此问题（matchedGan=藏干=透干，同一字）。

## 二、修复实现（js/bazi.js，仅 source 文案构造）

区分条件从「是否为月支藏干精确匹配」判定：

```js
: (cangGan.indexOf(matchedGan) >= 0
    ? '月支' + mZhi + '藏' + matchedGan + '，透于' + matchedPillar + ' → ' + ss
    : '月支' + mZhi + '本气' + benQi + '，为日主' + dayGan + '之' + ss + '；' + matchedPillar + '透' + matchedGan + '，同属' + benQiWx + '气，强化月令' + ss + '之势 → 取' + p.name)
```

- 精确匹配（matchedGan ∈ 月支藏干，含杂气月透中气/余气）→ 原文案不动。
- 同五行兜底 → 新文案：**月支实际藏干（本气）与外透同五行干分开描述**，不再把外透干写成「月支所藏」。
- matchedPillar 同步去掉「(同X透)」括号——新文案已完整表达同气强化之义，括号冗余。

产出示例：「月支寅本气甲，为日主丁之正印；年柱透乙，同属木气，强化月令正印之势 → 取正印格」。

1. **杂气月 indexOf 修正（关键自我纠错）**：第一版以 `matchedGan === benQi` 区分精确/兜底，107 盘 diff 暴露 5 个杂气月盘（M05 乙丑 癸未 庚辰 丙子 未月透余气乙、M07、M09、BND08、B2）——matchedGan 精确匹配中气/余气但 ≠ 本气，被误路由到新格式，生成「乙同属土气」式五行错误假文案。改为 `cangGan.indexOf(matchedGan) >= 0`（精确匹配 ⟺ 在月支藏干中）后归零；并给 scan 增加强化断言（透干必须 ≠ 本气且五行相同）防止同类错误再犯。

3. **GPT 推荐文案 vs 实现文案逐点对照**：GPT 版「月支寅本气甲，为日主丁火之正印；年柱乙木同五行透出，强化月令印星之势 → 取正印格」；实现版以十神名变量 ss 复用（正印）、日主用干名（丁）、措辞程序化（「年柱透乙，同属木气」）——语义等价、无事实差异，避免了新增十神→星名映射表。

5. **sha 口径纠错（Claude 自身失误，已修正）**：首轮重钉时用 PowerShell `ReadAllText` 算「LF sha」，该方法检测 UTF-8 BOM 后**静默剥离 BOM**，得到 f792041b（无 BOM 口径），据此钉了 12 个 harness——与 harness 的原始字节比对口径不符，会误报漂移。经 git blob 头 3 字节取证（63fafaa/97c3811/d46fbea/f4f217b 均为 EF BB BF）：**js/bazi.js 自 P3-A3 起仓库内长期含 BOM**，旧 pin 7c7af8bd 本就是含 BOM 的 blob sha，线上原始字节 == blob 一直成立。已改钉为真实 blob sha 677a95f3。教训：本仓库 sha 一律用「原始字节」（ReadAllBytes / git show | sha256sum）口径，禁用会剥 BOM 的文本读取路径；BOM 属历史遗留字节、浏览器与 Node 均按空白处理、不影响引擎，是否清除交 GPT 裁决，不在本修复内动冻结字节。
